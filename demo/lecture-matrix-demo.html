Lecture Rating Matrix

A rubric that scores a recorded lecture out of 10 on topic coverage, examples, and hands-on implementation, read from its transcript. This page shows the rubric, the scores it produced on four real lectures, and a live run of the automated signal-extraction stage.

01 — The instrument

The rubric

Ten points split across four weighted dimensions, each broken into sub-criteria that carry their own point cap. The decomposition is deliberate: every score can be traced to the criterion that produced it, so a disagreement is settled line by line instead of re-arguing the total.

Dimension Code Sub-criterion What it measures Max

Topic Coverage and Implementation carry the most weight because they are the two things the lecture rating was asked to measure. Delivery and Structure is kept deliberately light at 1.5 points so that a well-organised but empty lecture cannot score well.

03 — What testing surfaced

The 1.0 was not a bad lecture

Failure found in week 2 testing

The pipeline scored the wrong video, correctly

The third Howard lecture scored 1.0 out of 10, near zero on every content dimension. The first assumption was an over-harsh rubric. Reading the raw transcript showed something else: it contained project deadlines, a guest-speaker announcement and a recruiting event, and no course content at all.

Howard splits each class period into several numbered YouTube segments, an announcements clip followed by the lecture itself, and the public course schedule linked the first segment. The pipeline had fetched exactly the URL it was given and scored it accurately. The content simply was not a lecture.

The real defect was in the output: a 1.0 reads identically whether a lecture was poor or was never a lecture. At scale that silently corrupts a dataset. The fix is a content-verification gate that runs before any rubric is applied — it is implemented in the panel below, and returns an explicit unverified status instead of a score.

04 — Running code

Stage 2, live

This panel runs the signal-extraction stage from lecture_rating_pipeline.py in your browser, using the same marker patterns and the same keyword-overlap logic as the script. Paste any transcript, or load one of the sample texts, and the counts recompute against it.

stage 2 · signal extraction + verification gate

A design decision this demo forced. The gate first tested transcript length and keyword overlap as equal conditions, failing on either. Running it against a short excerpt of a genuine lecture showed the flaw immediately: length alone flags real content. Topic overlap is the decisive signal — it is what separated the announcements clip from the lectures — and length now only corroborates it.

A bug this demo surfaced. Porting the patterns exactly revealed that the e.g. marker in the current script never fires in normal prose. Its trailing word boundary requires a letter straight after the final period, so e.g. a seating chart does not match while e.g.a does. Every example marked with e.g. has been going uncounted. One-line fix, queued for the next commit.

Sample texts are paraphrased stand-ins written for this demo, not verbatim captions. The marker counts shown are real counts computed on whatever text sits in the box.
